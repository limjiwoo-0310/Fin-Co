## 02. 기획 의도

**배경:** 입양과 상관없이 관상어를 구경하기 위해 사이트에 들어가면 항상 생명을 상품처럼 다루는 느낌을 받음, 또한 어떤 조건에서 생물을 키울 수 있는지 확인할 수 없는 경우가 많아 섣부른 판단을 할 까 걱정이 됨. 사육 난이도나 필요한 물품들도 직접 찾아보던 것에 어려움을 느낌.

**목표:** 품종 도감에서 특징을 살펴보고, 마음에 드는 베타의 난이도와 적정 환경을 확인한 뒤 입양까지 한 곳에서 할 수 있게 함.

- 방문자가 받길 원한 인상: 단정하고 정리된, 믿을 수 있는 (prd)
- 방문자가 "이 베타를 내가 키울 수 있겠다"를 먼저 확인한 다음 입양을 고르는 경험을 목표로 설정

- **타깃 사용자:** 첫 베타 입문자(주), 베타 애호가·수집가(보조). 주요 기기는 PC 우선, 모바일은 기본 대응

### 타깃 페르소나

#### 주 페르소나 — 김하늘, 첫 베타 입문자

**기본 정보**

| 항목           | 내용                                                             |
| -------------- | ---------------------------------------------------------------- |
| 가명           | 김하늘 (초안)                                                    |
| 연령대         | 20대 (초안)                                                      |
| 방문자 유형    | 첫 베타 입문자 — 우선 방문자 (prd)                               |
| 베타 사육 경험 | 없음. 키워 볼지 고민하는 단계 (prd)                              |
| 주로 쓰는 기기 | PC (prd: PC 우선)                                                |
| 한 마디        | "예쁜 건 알겠는데, 내가 이 아이를 제대로 키울 수 있을까?" (초안) |

**상황**

- 베타를 처음 키워 보기로 마음먹었지만, 품종이 여러 가지라 서로 무엇이 다른지, 어떤 품종이 키우기 쉬운지 모름.
- 수온 · 어항 크기 · 여과기 · 합사 가능 여부, 먹이를 주는 방법을 알려면 블로그와 커뮤니티를 여러 곳 찾아봐야 함.
- 어떤 어항 세트와 용품이 필요한지, 모두 합치면 얼마가 드는지 몰라 시작 예산을 세우기 어려움.
- 생명을 들이는 일이라, 고르기 전에 "내가 키울 수 있는지"를 먼저 확인하길 원함.

**목표**

1. 품종별 키우기 난이도를 비교해 자신에게 맞는 품종을 고른다. (prd)
2. 고른 품종의 적정 환경(사육 환경 · 먹이 급여 방법)을 미리 알아 둔다. (prd)
3. 필요한 세트와 총비용을 확인한다. (prd)
4. 마음에 드는 개체를 확인한 뒤 입양을 신청한다. (prd)

**페인 포인트**

1. 쇼핑 사이트는 개체를 상품처럼 가격 순으로 나열해서, 키울 수 있는지 알기 전에 가격부터 보게 된다.
2. 개체를 골라도 그 품종의 난이도와 적정 환경을 같은 화면에서 확인할 수 없다.
3. 사육 정보 · 필요한 물품 · 입양 신청이 서로 다른 곳에 흩어져 있어 직접 찾아 모아야 한다.
4. 입문자라 어떤 정보가 꼭 필요한지 몰라, 신청할 때 무엇을 준비해야 하는지도 막막하다.

**이 사이트를 사용하는 상황**

| 언제 (초안)                                     | 사이트에서 하는 일 (구현)                                                                        | 관련 요구사항 |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------ | ------------- |
| 주말 저녁, 집 PC로 어떤 품종을 키울지 고민할 때 | 첫 화면 "품종 도감 보기 →"로 "다양한 베타 모아보기"에 가서 품종 카드 6종을 넘겨 본다             | R-02, R-03    |
| 이 품종을 키울 수 있을지 궁금할 때              | 품종 카드를 눌러 팝업에서 키우기 난이도 · 특징 · 적정 환경(수온 · 어항 · 여과기 · 합사)을 읽는다 | R-04          |
| 무엇이 필요하고 얼마가 드는지 알고 싶을 때      | "사육 환경 가이드"에서 적정 사육 환경, 먹이 급여 방법, 추천 세트 3종의 총비용을 본다             | R-06          |
| 품종을 정했을 때                                | 품종 팝업의 "○○ 입양 가능 개체 보기"로 "함께할 베타 찾기"에 간다                                 | R-09, R-11    |
| 신청 전에 개체를 확인할 때                      | 개체 팝업에서 품종 · 색·패턴 · 성별 · 나이 · 입양비와 품종 난이도 · 환경 요약을 읽는다           | R-15          |
| 입양을 신청할 때                                | 같은 팝업의 신청서를 채워 제출한다. 빠뜨린 칸은 경고로 알 수 있다                                | R-16 ~ R-18   |
| 신청을 마친 뒤                                  | 완료 팝업의 "사육 가이드 보기"로 사육 환경 가이드를 다시 본다                                    | R-05          |

**사이트가 페인 포인트를 해결하는 방식**

| 페인 포인트                      | 사이트의 해결 (구현)                                                                                       |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 1. 가격부터 보게 된다            | 개체 카드에는 금액을 표시하지 않고, 입양비는 개체 팝업 안에서 정보와 함께 보여 준다 (R-11, R-15)           |
| 2. 난이도·환경을 함께 볼 수 없다 | 개체 팝업 안에 그 품종의 키우기 난이도와 환경 요약을 함께 넣었다 (R-15)                                    |
| 3. 정보가 흩어져 있다            | 품종 도감 → 사육 가이드 → 입양 가능 개체 → 신청서를 한 사이트, 한 팝업 흐름으로 이었다 (R-09, R-16 ~ R-18) |
| 4. 무엇을 준비할지 막막하다      | 신청서에 사육 경험 · 어항 준비 상태를 묻고, 필수 항목을 빠뜨리면 그 칸에 경고를 보여 준다 (R-16, R-17)     |

**성공 기준** — 품종 도감에서 시작해 입양 신청 완료 팝업까지 중간에 막히지 않고 간다. (TC-21 통과)

**기본 정보**

| 한 마디        | "블루 계열 새 개체 들어온 거 없나?" (초안)             |

**상황**

- 이미 베타를 키우고 있고, 특정 색·패턴의 새 개체를 찾고 있다.
- 희귀 품종이나 새로 들어온 개체 소식을 놓치지 않으려고 사이트를 자주 확인한다.
- 기초 사육 정보보다 수질 관리 · 질병 대처 · 번식 · 발색 관리 같은 깊은 정보가 필요하다.

**목표**

- 원하는 색·패턴의 개체만 골라 본다. (prd)
- 희귀 품종과 입고 소식을 확인한다. (prd)
- 심화 사육 정보를 읽는다. (prd)

**페인 포인트**

1. 원하는 색의 개체를 찾으려면 전체 목록을 처음부터 끝까지 넘겨 봐야 한다.
2. 입고 소식이 따로 정리되어 있지 않아 새 개체를 늦게 알게 된다.
3. 입문자용 정보만 있고, 심화 사육 정보는 다른 곳에서 찾아야 한다.

**이 사이트를 사용하는 상황**

## 03. 핵심 가설

- **가설 설정 배경 한 줄:** (초안) 사이트 목적을 "확인한 뒤 입양까지 한 곳에서"로 정했고(prd), 품종·개체 상세를 별도 페이지가 아닌 팝업으로 열어 목록 위치를 유지하기로 했습니다(PROJECT_CONTEXT). 이 구조가 입양 신청까지 이어지는지 확인하고 싶었습니다.
- **IF-THEN**
  - **IF** (초안) 개체 카드를 누르면 같은 팝업 안에서 개체 정보 → 품종 난이도·환경 요약 → 입양 신청서가 차례로 이어지고, 빠뜨린 필수 칸은 그 자리에서 알려 준다면
  - **THEN** (초안) 첫 베타 입문자는 페이지를 옮기지 않고 신청서를 끝까지 채워, 입양 신청 완료 화면(P-04)까지 간다.
- **검증 방향:** (초안) 주요 동선을 처음부터 끝까지 따라가는 사용 흐름 테스트 TC-21(PC)·TC-22(휴대폰)로 P-04 도착 여부를 확인합니다. 신청서 단계는 TC-15·TC-17·TC-18로 나눠 확인합니다. (TC)

## 05. 인터랙션 설계

### 사이트 구성 한눈에 보기

```
P-01 메인 원페이지
 S-01 상단 메뉴(고정)
 S-02 첫 화면 ─────────────── [인터랙션 ③ 물결]
 S-04 품종 도감 ── 카드 클릭 ─▶ P-02 품종 상세 팝업 ── [인터랙션 ①]
 S-05 사육 가이드 ─ B-03 ──▶ P-05 심화 사육 정보(/advanced)
 S-06 입양 가능 개체 ◀── B-11 ──┘
   └ 카드 클릭 ─▶ P-03 개체 상세 · 입양 신청 ── [인터랙션 ②]
                    └ B-13 제출 ─▶ P-04 입양 신청 완료 ─ B-16 ─▶ S-05
 S-08 세트·용품 / S-09 입고 소식 / S-10 푸터
```

- 주요 동선: S-04 품종 도감 → P-02 품종 상세 → S-06 입양 가능 개체 → P-03 개체 상세·입양 신청 → P-04 입양 신청 완료 (prd)
- 사이트 형태: 메인 원페이지 + 상세 팝업 2종(+완료 팝업) + 별도 페이지 1개. 로그인·회원가입은 넣지 않았습니다. (PROJECT_CONTEXT)
- ✏️ 직접 채우기: Figma 사이트맵(node-id=3-3) 캡처를 넣으면 좋습니다.

### 인터랙션 ① 목록 위에 여는 상세 팝업

- **무엇을:** 품종·개체 카드를 누르면 목록 위에 회색 배경과 가운데 모달(폭 880px)이 열립니다. 닫기 또는 회색 배경을 누르면 열기 전 스크롤 위치로 돌아갑니다. 닫기 버튼은 팝업 안을 스크롤해도 오른쪽 위에 고정됩니다. 품종 팝업 맨 아래 "{품종명} 입양 가능 개체 보기"는 팝업을 닫고 입양 목록으로 이동합니다. (PROJECT_CONTEXT)
- **왜:** 품종·개체 상세를 별도 페이지로 나누지 않고 팝업으로 열어 목록 위치를 유지하기 위해서입니다. (PROJECT_CONTEXT) (초안) 품종을 비교하다가 상세를 봐도 흐름이 끊기지 않아야, 가설의 "페이지를 옮기지 않고 끝까지 간다"가 가능하다고 보았습니다.
- **어떻게:** React 공통 모달 컴포넌트(`Modal.jsx`, `CloseButton.jsx`)로 P-02~P-04를 같은 방식으로 엽니다. 터치 기기에서는 아래에서 올라오는 화면 폭 전체 시트로 열고, 열린 동안 뒤 페이지 스크롤을 잠급니다. (PROJECT_CONTEXT, interaction.md)

### 인터랙션 ② 개체 팝업 안 입양 신청서와 필수 항목 검사

- **무엇을:** 개체 팝업 안에서 개체 정보 5행 → 품종 난이도·환경 요약 → 신청서(이름·연락처·키워 본 경험·어항 준비 상태·희망 인계 방법·희망 날짜)가 이어집니다. 필수 4칸이 비어 있으면 칸 아래 빨간 경고와 빨간 테두리가 나타나고 첫 번째 빈 칸으로 이동합니다. 다시 입력하면 그 칸의 경고만 사라집니다. 다 채우고 "입양 신청하기"를 누르면 실제 전송 없이 완료 팝업으로 바뀝니다. (PROJECT_CONTEXT)
- **왜:** 사이트의 가장 중요한 행동이 입양 신청이기 때문입니다. (prd) 신청 전에 개체 정보와 품종 난이도·환경 요약을 확인할 수 있게 했습니다(R-15). 필수 항목을 빠뜨렸을 때 어느 칸을 채워야 하는지 알 수 있게 했습니다(R-17). (prd) (초안) 신청서 바로 위에 난이도와 환경을 두어 "알고 고르는" 마지막 확인을 하게 했습니다.
- **어떻게:** `FishModal.jsx`에서 제출 시 필수 4칸을 검사합니다. 선택 옵션은 선택한 항목 아래로 면이 튕기며 미끄러지는 GlideChips 컴포넌트를 씁니다. 휴대폰에서는 입력칸 글자를 16px로 키워 아이폰 자동 확대를 막았습니다. (PROJECT_CONTEXT, interaction.md)
- 범위 제외: 실제 전송, 저장, 개인정보 동의, 연락처 형식·지난 날짜 검사 (prd)

### 인터랙션 ③ 첫 화면 물결과 순차 등장

- **무엇을:** 첫 화면 이미지 위에서 마우스를 움직이면 커서 주변 물이 약하게 일렁입니다. 라벨 → 슬로건 1줄 → 슬로건 2줄 → "품종 도감 보기" 버튼이 0.3초 간격으로 떠오릅니다. (PROJECT_CONTEXT)
- **왜:** 어항 속 물의 움직임을 직접 떠올리게 해서 "베타 전문 어항 브랜드"라는 정체를 첫 화면에서 감각적으로 전달하기 위해서입니다. (reference)
- **어떻게:** WebGL로 구현했습니다(`useHeroRipple.js`). 터치 기기, 움직임 줄이기 설정, WebGL2 미지원 환경에서는 정지 이미지를 보여 줍니다. (PROJECT_CONTEXT)

**3) 발견한 문제와 개선 — TC-18**

| 구분                   | 내용                                                                                                                                                                                                                       |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 무엇을 확인하는 케이스 | 입양 신청서를 제출하면, 실제 전송 없이 완료 팝업이 뜨는지 (R-18)                                                                                                                                                           |
| 처음 판단              | **실패** — 참여자가 "Network(네트워크) 탭에 아무것도 뜨지 않는다"고 알려 옴                                                                                                                                                |

- **배운 점 (초안):** 실패가 나왔을 때 바로 코드를 고치지 않고, 먼저 코드가 무엇을 하는지 확인했습니다. 이번 실패는 사이트가 아니라 **테스트 문서의 문장**이 원인이었습니다. "생기지 않는다"처럼 없는 것을 확인하는 기대 결과는, 화면에서 무엇이 보이면 정상인지("목록이 비어 있다")로 써야 한다는 것을 알게 됐습니다.
